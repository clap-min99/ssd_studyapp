## 이번 레슨의 목표

RAM 배열 선언과 동기 쓰기·비동기 읽기를 추적하고 ROM case의 완전 할당을 확인합니다.

## 앞에서 배운 내용

4장의 always_ff와 assign을 메모리 인터페이스에 적용합니다. 레슨20의 레지스터 파일보다 단순한 단일 주소 RAM부터 봅니다.

## 동일한 배열에도 접근 시점의 약속이 필요하다

```systemverilog
module ch5_ram8x8(input logic clk, we,
                  input logic [2:0] addr, input logic [7:0] din,
                  output logic [7:0] dout);
  logic [7:0] mem [0:7];
  always_ff @(posedge clk)
    if (we) mem[addr] <= din;
  assign dout = mem[addr];
endmodule

module ch5_rom4x2(input logic [1:0] addr,
                  output logic [1:0] data);
  always_comb begin
    case (addr)
      2'b00: data = 2'b00;
      2'b01: data = 2'b10;
      2'b10: data = 2'b10;
      2'b11: data = 2'b01;
      default: data = '0;
    endcase
  end
endmodule
```

`logic [7:0] mem [0:7]`는 8비트 워드 여덟 개입니다. 앞의 범위는 워드 안의 비트, 뒤의 범위는 워드 인덱스입니다. RAM 쓰기는 상승 에지에서 we=1일 때만 일어납니다. 읽기는 주소 또는 해당 메모리 내용이 바뀌면 조합적으로 반영됩니다. 초기 내용은 쓰기나 초기화 전까지 미지입니다.

같은 주소를 읽으며 쓰면 에지 직전에는 옛 값이고 nonblocking 갱신 및 조합 평가 뒤에는 새 값입니다. 같은 에지에 읽기 출력을 저장하는 다른 레지스터는 직전 값을 읽는 모델입니다. FPGA의 특정 RAM 블록은 동기 읽기나 별도 read-during-write 정책을 요구할 수 있으므로 합성 추론 보고를 확인해야 합니다. 비동기 읽기 코드를 적었다고 모든 장치의 전용 block RAM이 같은 형태로 사용되는 것은 아닙니다.

ROM은 레슨21의 자체 표를 코드로 옮겼습니다. 모든 정상 주소와 default에서 출력이 정해져 저장 래치가 생기지 않습니다. RAM은 상태를 갖지만 고정 ROM 함수의 읽기 논리는 조합논리로 표현할 수 있습니다. 전체 메모리를 reset으로 지우는 코드는 구현 비용과 추론을 바꿀 수 있으므로 초기값 요구가 있을 때 별도로 설계합니다.

## 메모리 검사에는 준비 쓰기와 관찰 시점이 필요하다

RAM의 상태는 행마다 다릅니다. 주소 3을 썼다고 주소 4의 값도 정해지지 않습니다. 검사에서는 먼저 사용할 행을 유효한 데이터로 초기화하는 준비 쓰기를 수행하고,그 뒤 유지·갱신·주소 독립성을 확인합니다. 물리 RAM 초기값을 별도 계약 없이 0으로 가정하지 않습니다.

상승 에지 쓰기와 비동기 읽기의 사건 순서를 분리하세요. 입력 addr,din,we를 에지 전에 준비하고 에지에서 쓰기를 예약합니다. 갱신 뒤 같은 주소의 dout이 새 값으로 반영됩니다. #1 뒤 관찰은 테스트의 경합을 피하는 모델 시간 간격이며 RAM의 실제 접근 시간을 측정하거나 지정하는 것은 아닙니다.

ROM은 같은 주소에 언제나 정한 데이터가 나오는 함수이고,이 RAM은 쓰기 이력에 따라 데이터가 달라집니다. 배열 선언 모양이 비슷해도 둘의 계약은 다릅니다. 합성 대상이 동기 읽기를 요구하면 출력 레지스터와 검사 기대 시점을 함께 바꾸어야 하며 코드 한 줄만 교체해서 끝내지 않습니다.

## 따라 풀기

addr=3,we=1,din=0x5A로 상승 에지를 맞으면 갱신 후 mem[3]=0x5A이고 dout도 0x5A입니다. we=0으로 바꾸고 din만 0xC3으로 바꿔도 저장값은 0x5A입니다. addr를 4로 바꾸면 dout은 mem[4]이며, 한 번도 쓰지 않았다면 시뮬레이션에서 X일 수 있습니다. ROM에 addr=3을 넣으면 주소 11의 데이터 01이 나옵니다.

### 조건을 바꾸어 한 번 더 풀기

각 행이 처음에는 미지라고 두고 다음 순서로 검사합니다.

| 단계 | 입력/사건 | 기대 |
| --- | --- | --- |
| 1 | addr=2,din=0xA5,we=1의 상승 에지 | 갱신 후 dout=0xA5 |
| 2 | addr=5,din=0x3C,we=1의 상승 에지 | 갱신 후 dout=0x3C |
| 3 | we=0,addr=2 | 조합 평가 후 0xA5 |
| 4 | we=0,din=0x00,상승 에지 | 여전히 0xA5 |
| 5 | addr=5 | 여전히 0x3C |

이 흐름은 행 독립성과 write-enable을 함께 확인합니다. 미작성 주소를 읽고 기대 0을 넣는 것보다 계약에 맞는 검사입니다.

## 헷갈리기 쉬운 점

RAM을 선언했다고 DRAM의 refresh가 이 코드에서 자동 구현되는 것은 아닙니다. 이 코드는 논리 메모리 모델이며 실제 저장 기술과 물리 인터페이스는 다른 층입니다. 검증에서 미작성 주소를 정답 0으로 가정하지 않습니다.

### 적용 문제: 직접 구성하고 이유 설명하기

주소 2에 0xA5를 썼는데 주소 5를 쓰자 주소 2도 바뀝니다. 주소 디코드가 일부 비트를 무시하는 버그를 의심할 때 왜 서로 다른 두 주소를 검사해야 하나요? 세 주소 비트 각각을 겨냥한 주소 쌍도 제안하세요.

<details>
<summary>적용 문제 풀이와 검산</summary>
<p>한 주소만 쓰고 읽으면 잘못된 주소가 같은 내부 행을 가리켜도 통과할 수 있습니다. 두 주소에 서로 다른 데이터를 쓰고 각각 보존되는지 봐야 별개 행인지 확인할 수 있습니다.</p>
<p>3비트 주소에서 (000,001),(000,010),(000,100)은 각각 한 비트만 다릅니다. 해당 비트를 무시하면 쌍이 충돌합니다. 이 검사는 모델의 주소 기능을 겨냥하며 실제 소자 결함 시험 전체는 아닙니다.</p>
</details>
