## 이번 레슨의 목표

블록의 폭·시간·부호·주소 명세를 함께 정하고 기능과 구현 타이밍의 검사 범위를 구별합니다.

## 앞에서 배운 내용

산술 회로로 값을 바꾸고 레지스터로 이력을 유지하며 배열에서 주소로 데이터를 골랐습니다. 같은 블록을 연결할 때도 인터페이스의 약속이 이어져야 합니다.

## 작은 누적기를 명세에서 추적표로 만든다

4비트 unsigned 누적기 Q를 만듭니다. active-high 동기 reset이 최우선이며, 그 외에는 en=1인 상승 에지에서 Q_next=(Q+data) mod 16을 저장합니다. en=0이면 유지합니다. data는 4비트, carry는 현재 Q+data의 5번째 비트이며 레지스터에 저장하지 않는 조합 관찰 신호입니다.

```systemverilog
module ch5_accumulator4(input logic clk, reset, en,
                        input logic [3:0] data,
                        output logic [3:0] q, output logic carry);
  logic [3:0] sum;
  assign {carry,sum} = {1'b0,q}+{1'b0,data};
  always_ff @(posedge clk)
    if (reset) q <= '0;
    else if (en) q <= sum;
endmodule
```

상승 에지는 직전 Q와 data에서 계산된 sum을 저장합니다. 갱신 후 carry도 새 Q와 같은 data에서 다시 계산되므로 ‘그 에지에 저장한 합의 캐리’를 나중에 읽으려면 별도 레지스터로 보존해야 합니다. 출력 이름만 보고 과거 사건의 플래그로 해석하지 않습니다.

메모리에서 data를 읽어 공급하려면 주소·메모리 읽기 지연·초기값을 명세합니다. 비동기 읽기 모델은 주소 변경 후 조합 경로로, 동기 읽기 메모리는 정해진 에지 이후에 나올 수 있습니다. 두 인터페이스를 그대로 바꾸면 누적하는 데이터의 순서가 달라질 수 있습니다.

검증에서는 4장 방식대로 하강 에지에 자극을 주고 상승 에지 직후 갱신이 끝난 다음 Q를 기대값과 비교할 수 있습니다. 기대값은 소프트웨어 정수로 합을 구해 16으로 나눈 나머지로 계산합니다. signed 비교·오버플로는 별도 명세가 없으므로 unsigned 누적 결과와 섞지 않습니다.

## 기능을 묶은 뒤 검사 벡터에 목적을 붙이기

누적기의 핵심은 저장값 q와 현재 조합 합 sum을 분리하는 것입니다. q가 9,data가 7이면 sum=0,carry=1이지만 en=0이면 q는 계속 9입니다. ‘연산 경로가 답을 냈다’와 ‘그 답을 저장했다’는 다른 사건입니다. enable·reset은 저장 쪽의 선택 계약입니다.

독립 기대값 모델은 이전 기대 q에서 시작해 reset이면 0,아니고 en이면 (q+data) mod 16,나머지는 유지로 갱신합니다. DUT의 현재 q를 읽어 기대값을 만들면 잘못된 상태를 다음 기대값에 섞을 수 있으므로 별도 모델 상태를 유지합니다.

검사는 정상 합,wrap,enable 유지,reset 우선순위,에지 사이 입력 변화를 각각 겨냥합니다. 메모리에서 data를 공급하는 시스템으로 확장하면 초기화한 주소의 내용과 읽기 지연도 기대값 이력에 들어갑니다. 블록 하나의 정답만으로 연결된 시스템의 샘플 순서가 맞다고 보장하지 않습니다.

## 따라 풀기

리셋 후 Q=0입니다. 아래 carry는 저장 직전의 합을 기준으로 적었습니다.

| 에지 | reset | en | data | 직전 Q | 직전 합 carry | 직후 Q |
| --- | --- | --- | --- | --- | --- | --- |
| E1 | 0 | 1 | 9 | 0 | 0 | 9 |
| E2 | 0 | 0 | 7 | 9 | 1 | 9 |
| E3 | 0 | 1 | 7 | 9 | 1 | 0 |
| E4 | 1 | 1 | 5 | 0 | 0 | 0 |

E2는 조합 합이 16이어도 en=0이므로 저장하지 않습니다. E3에서만 하위 4비트 0을 저장합니다. E3 직후에는 Q=0,data=7이므로 조합 carry는 0으로 바뀝니다. 이 차이를 검사 시점에 반영해야 합니다.

### 조건을 바꾸어 한 번 더 풀기

reset 후 q=0에서 data=6,en=1을 두 에지 주면 6,12입니다. 이어 data=5,en=0이면 조합 합은 17이라 carry=1이지만 q는 12입니다. 다음 en=1 에지에서 q=1로 wrap합니다.

그 에지 직전의 carry=1을 ‘방금 발생한 넘침’으로 나중에 읽고 싶다면 carry도 에지에서 저장해야 합니다. 현재 코드의 carry는 갱신 후 q=1,data=5를 다시 더해 0으로 바뀝니다. 기능 명세를 기록할 때 저장 플래그인지 현재 조합 신호인지 이름과 설명에 드러내세요.

## 헷갈리기 쉬운 점

기능 모델이 맞아도 실제 setup·hold·스큐를 별도로 검사해야 합니다. 선택 심화를 모두 외우는 것보다 입력 폭·부호·현재/다음 상태·읽기 시점을 일관되게 설명하는 것이 핵심입니다. 산업 수치·현재 제품·원문 연습문제 전체 풀이는 이 장에 포함하지 않습니다.

### 적용 문제: 직접 구성하고 이유 설명하기

q=14에서 시작해 (reset,en,data)를 (0,0,3),(0,1,3),(1,0,9),(0,1,9) 순서로 적용합니다. 매 에지 직전의 합 carry와 직후 q를 구하세요. 마지막 값을 signed로 읽으면 무엇이며,이 모듈의 unsigned 계약과 어떻게 구분하나요?

<details>
<summary>적용 문제 풀이와 검산</summary>
<p>직전 합 carry/직후 q는 순서대로 1/14,1/1,0/0,0/9입니다. 첫 번째는 계산이 넘쳐도 유지,세 번째는 en=0이어도 reset이 우선합니다.</p>
<p>마지막 패턴 1001을 signed로 읽으면 −7이지만 이 누적기의 계약에서는 unsigned 9입니다. signed overflow 정책을 원하면 별도 요구사항과 검사 모델을 추가해야 합니다.</p>
</details>
