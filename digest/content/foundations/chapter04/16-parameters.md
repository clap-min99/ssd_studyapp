## 이번 레슨의 목표

선택 심화입니다. parameter의 기본값·재정의와 실행 중 입력을 구별하고 매개변수 디코더의 출력을 계산합니다.

## 앞에서 배운 내용

레슨 6에서는 고정 폭의 작은 모듈을 연결했습니다. 폭만 다른 같은 기능을 매번 복사하지 않도록 매개변수로 묶습니다.

## 회로를 구성할 때 정하는 상수다

```systemverilog
module choose_n #(parameter int W = 5)
  (input logic [W-1:0] a, b, input logic s,
   output logic [W-1:0] y);
  assign y = s ? b : a;
endmodule

module choose10(input logic [9:0] a, b, input logic s,
                 output logic [9:0] y);
  choose_n #(.W(10)) u_pick(.a(a), .b(b), .s(s), .y(y));
endmodule
```

W는 기본 5이며 인스턴스에서 이름 기반 `#(.W(10))`으로 10으로 정했습니다. 회로를 구성하는 elaboration 단계에서 포트 폭과 구조가 결정됩니다. 동작 중 s를 바꾸면 입력 선택이 바뀌지만 W를 입력처럼 매 주기 바꿀 수는 없습니다. 이 예제는 W≥1을 전제로 합니다. W=0이면 `[W-1:0]`이 빈 버스가 된다고 가정하지 말고 유효하지 않은 설정으로 취급합니다.

아래는 N비트 주소를 2의 N승 개 출력으로 바꾸는 디코더입니다. N은 작은 양의 정수로 제한해 사용합니다.

```systemverilog
module decode_n #(parameter int N = 2)
  (input logic [N-1:0] addr,
   output logic [(2**N)-1:0] onehot);
  always_comb begin
    onehot = '0;
    onehot[addr] = 1'b1;
  end
endmodule
```

먼저 전체 출력을 0으로 만든 뒤 선택한 비트만 1로 덮어씁니다. 기본값은 매 조합 평가마다 적용되므로 이전 주소의 1이 남지 않습니다. 코드의 별표 두 개는 거듭제곱이며 XOR인 `^`와 다릅니다. N이 하나 늘 때 출력 폭은 두 배가 되므로 간단한 코드라도 회로 비용이 빠르게 늘 수 있습니다. VHDL에서는 이 역할에 generic을 사용합니다.

## 매개변수 값으로 실제 포트 범위를 계산하기

choose_n의 W는 회로를 구성할 때 치환하는 상수입니다. 기본 W=5이면 `[W-1:0]`는 [4:0], 인스턴스에서 W=10으로 재정의하면 [9:0]이 됩니다. 먼저 이렇게 구체 범위로 바꿔 보고 각 포트와 연결 신호의 폭이 같은지 확인하세요. 실행 중에 W가 변해 버스가 늘었다 줄었다 하는 모델이 아닙니다.

decode_n은 주소 폭 N과 출력 개수가 다른 속도로 늘어납니다. 주소는 N비트지만 onehot의 길이는 2ᴺ입니다. N=2일 때 4개, N=3일 때 8개, N=4일 때 16개입니다. 버스 폭을 바꾸는 재사용은 편리하지만 합성되는 논리량까지 작다는 뜻은 아닙니다.

onehot 전체를 매 평가마다 0으로 만든 다음 선택한 위치 하나만 1로 덮는 순서가 중요합니다. 이 기본 할당이 빠지면 새 주소 비트 하나만 바뀌고 이전 위치의 1이 남는 저장 의미가 생길 수 있습니다. 주소가 미지이면 정상 one-hot 계약도 보장할 수 없으므로 입력 유효성은 별도로 검사합니다.

## 따라 풀기

choose10에서 a=10'b00000_00101, b=10'b10000_00001, s=1이면 y=b입니다. 10비트 폭이므로 상위 1도 보존됩니다. decode_n의 N=3이면 출력 폭은 2³=8비트이고 addr=101₂=5이면 onehot[5]=1, 나머지 0이므로 00100000₂입니다. addr=2로 바꾸면 00000100₂로 바뀌어 이전 bit5는 0이 됩니다.

### 조건을 바꾸어 한 번 더 풀기

N=2인 디코더의 주소를 0→2→1로 바꿉니다.

| 주소 | 기본값 적용 | 선택 비트 갱신 후 |
| --- | --- | --- |
| 00 | 0000 | 0001 |
| 10 | 0000 | 0100 |
| 01 | 0000 | 0010 |

기본 0 대입이 매번 반복되므로 0101이나 0111처럼 누적되지 않습니다. N=3으로 바꾸면 같은 주소 2의 결과는 8비트 00000100으로 폭이 바뀌지만 선택 원리는 같습니다.

## 헷갈리기 쉬운 점

#(.W(10))은 매개변수 재정의이고 #10은 시뮬레이션 지연이므로 같은 # 기호라도 문맥이 다릅니다. 매개변수의 폭과 연결 신호 폭이 맞는지 확인합니다. 디코더에서 미지 주소는 정상 one-hot 출력을 보장하지 않으며 검증 대상입니다.

## 직접 확인하기

1. W=7이면 choose_n의 입력 a는 몇 비트인가요?
2. N=4 디코더의 출력 폭과 addr=3의 패턴은 무엇인가요?
3. parameter를 입력 포트처럼 매 클록 갱신할 수 있나요?

### 적용 문제: 직접 구성하고 이유 설명하기

W=12로 choose_n을 인스턴스화했는데 출력 신호가 8비트입니다. b의 상위 네 비트만 1인 입력을 선택하면 무엇이 사라질 수 있나요? 연결 전에 작성할 폭 표를 제시하세요.

<details>
<summary>적용 문제 풀이와 검산</summary>
<p>b=12'b1111_0000_0000,s=1이면 모듈 y는 12비트 111100000000입니다. 8비트 신호로 받으면 상위 1111이 잘려 00000000만 남을 수 있습니다.</p>
<p>포트 a,b,y 각각 12비트, 선택 s 1비트, 상위 연결 a,b,y 각각 12비트인지 표로 대조해야 합니다. 매개변수 재정의와 상위 신호 선언을 함께 바꿉니다.</p>
</details>
