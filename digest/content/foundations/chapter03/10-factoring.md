## 이번 레슨의 목표

서로 다른 역할의 상태를 분리하고, 두 FSM이 주고받는 신호가 어느 에지에서 효력을 갖는지 설명합니다.

## 앞에서 배운 내용

1장에서 큰 설계를 작은 블록으로 나누는 계층화와 모듈성을 배웠습니다. 상태 머신에도 같은 원리를 적용할 수 있습니다. 단, 역할을 나눴다고 상태의 조합이나 시간 관계가 사라지지는 않습니다.

## 모드 기억과 작업 제어 분리하기

레슨 7의 작업 표시기에 pause 입력을 추가한다고 합시다. 이 예제는 pause를 저장한 모드 P가 1인 동안 새 작업을 받지 않고, 이미 Busy인 작업은 정상 완료합니다. pause 입력의 변경은 모드 레지스터를 거쳐 접수 조건에 반영됩니다. 입력은 모두 같은 클록에 동기화되어 있다고 가정합니다.

먼저 모드 FSM의 상태 P는 ‘일시정지 중인가’를 저장합니다. 매 에지에 `P_next=pause`로 갱신합니다. 작업 FSM은 Idle·Busy·Report를 유지하고 Idle의 시작 조건만 `start·¬P`로 바꿉니다. 여기서 작업 FSM이 참조하는 P는 현재 모드입니다.

## 따라 풀기

에지 전 P=0, 작업 상태 Idle이고 pause=1, start=1이라고 합시다. 모드의 다음 상태는 P_next=1입니다. 작업의 다음 상태는 **현재 P=0**을 사용하므로 Busy입니다. 에지 후 P=1, Busy가 됩니다. 새 P가 같은 에지의 작업 판단에 거꾸로 적용되지 않습니다.

이것이 원하는 명세인지 확인해야 합니다. ‘pause 입력이 1인 바로 그 에지부터 접수를 막는다’가 요구라면 Idle 조건을 `start·¬pause`로 바꾸거나 모드와 입력을 함께 고려해야 합니다. 그 변경은 단순 배선 정리가 아니라 관측 동작의 변경입니다.

P=1인 동안 Busy에서 done=1이면 Report로 가고 이어 Idle로 갑니다. Idle에서는 start=1이어도 유지합니다. pause=0을 샘플한 에지 후 P=0이 되면, 그 다음 에지부터 start를 받아들일 수 있습니다.

## 두 FSM의 상태를 한 표에서 추적하기

다음은 리셋 후 P=0, Idle에서 시작한 입력열입니다. 각 행의 입력은 해당 에지 전에 안정되어 있고, 모든 다음 상태는 에지 직전 값으로 계산합니다.

| 에지 | 직전 P / 작업 상태 | pause, start, done | 직후 P / 작업 상태 |
| --- | --- | --- | --- |
| E1 | 0 / Idle | 1, 1, 0 | 1 / Busy |
| E2 | 1 / Busy | 1, 0, 1 | 1 / Report |
| E3 | 1 / Report | 1, 1, 0 | 1 / Idle |
| E4 | 1 / Idle | 0, 1, 0 | 0 / Idle |
| E5 | 0 / Idle | 0, 1, 0 | 0 / Busy |

E1에서는 새 pause=1이 아니라 현재 P=0을 보고 작업을 접수합니다. E4에서는 반대로 pause=0을 읽어도 현재 P=1이라 접수하지 않습니다. E5에서야 start를 받습니다. 두 FSM을 소프트웨어 문장처럼 ‘모드 갱신 후 작업 갱신’ 순서로 계산하면 E1과 E4의 답이 모두 달라집니다.

## 분해의 효과와 한계

한 FSM에 모든 조합을 그리면 최대 2모드×3작업 상태=6개가 필요합니다. 분해하면 2상태 도표와 3상태 도표로 역할을 나눠 읽을 수 있지만 합성한 시스템의 상태 공간은 여전히 최대 6개입니다. 이진 구현이라면 모드 1비트와 작업 2비트로 총 3비트여서 저장 비트가 자동 감소하는 것도 아닙니다.

## 헷갈리기 쉬운 점

두 FSM이 서로의 현재 상태를 보는 것과 서로의 조합 다음 상태를 순환 참조하는 것은 다릅니다. 후자는 레지스터 없는 조합 고리를 만들 수 있습니다. 분해의 목적은 명세와 검증의 역할을 명확히 하는 것이며, 분해 전후의 출력·에지별 동작이 같은지도 검사해야 합니다.
