## 이번 레슨의 목표

주소와 저장된 값을 구별하고, C의 `&`·`*`·포인터가 하는 일을 설명합니다. 레지스터에 쓰는 코드가 하드웨어 동작으로 이어지는 경로를 말할 수 있으면 됩니다.

## 앞에서 배운 내용

STM32나 AVR에서 핀을 설정하고 모터를 움직여 본 경험을 떠올려 봅시다. 이번 장은 실습을 반복하기 전에 코드 한 줄의 의미를 정리합니다. 변수·대입은 알고 있다고 가정하고, 포인터는 여기서 다시 설명합니다. 보드는 없어도 됩니다.

## 개념과 동작

**주소(address)** 는 위치를 가리키고, **값(value)** 은 그 위치에서 읽는 내용입니다. 우편함 번호와 우편함 안의 편지가 다른 것과 같습니다. `0x`는 16진수 표기이며, 주소와 값 양쪽에 쓸 수 있습니다. 표기만으로 주소인지 값인지 판단할 수는 없습니다.

다음은 실제 칩의 주소가 아닌 교육용 메모리 지도입니다. 한 칸은 1바이트이고, 이 예에서 1바이트는 8비트입니다.

| 주소 | 저장된 값 | 해석 |
| --- | --- | --- |
| 0x2000 | 0x05 | 십진수 5 |
| 0x2001 | 0xA0 | 십진수 160 |

CPU가 0x2000을 읽으면 얻는 값은 0x05입니다. 0x2000에 0x09를 쓰면 위치는 그대로이고 내용이 9로 바뀝니다.

**포인터(pointer)** 는 객체의 주소를 담는 C 자료형입니다. `&변수`는 주소를 구하고, `*포인터`는 가리키는 객체에 접근합니다. 선언의 `*`는 포인터 자료형을 표시하고, 식의 `*`는 역참조(dereference)입니다. 곱셈과도 문맥이 다릅니다.

## 코드 읽기

아래는 일반 C11 프로그램입니다. `uint32_t`는 제공되는 구현에서 부호 없는 정확히 32비트 정수형입니다. `assert`는 괄호 안 조건이 거짓이면 실패를 알리는 검사입니다.

```c
#include <stdint.h>
#include <assert.h>

int main(void)
{
    uint32_t level = 5u;
    uint32_t *p = &level;
    uint32_t before = *p;
    *p = 9u;
    assert(before == 5u);
    assert(level == 9u);
    assert(p == &level);
    return 0;
}
```

`5u`의 `u`는 부호 없는 정수 상수라는 뜻입니다. `p = &level`은 주소를 저장합니다. `before = *p`는 그 시점의 값 5를 복사합니다. `*p = 9u`는 p의 주소를 바꾸는 대신 대상 level을 바꿉니다. 따라서 before는 계속 5입니다. 복사한 일반 정수는 원본 변화에 따라 자동으로 바뀌지 않습니다.

`p + 1`은 숫자 주소에 무조건 1바이트를 더한다는 뜻이 아닙니다. 포인터 산술은 대상 자료형 크기 단위이며 같은 배열 범위와 그 끝 다음 위치라는 C의 제한을 따릅니다. 아무 하드웨어 주소에 포인터 산술을 적용해도 된다고 일반화하지 않습니다.

## 따라 풀기

1. `level`이 만들어지고 값 5가 저장됩니다. 실제 주소는 실행 환경이 정합니다.
2. p에는 그 주소가 들어갑니다. p 자체도 하나의 변수입니다.
3. before는 `*p`로 읽은 5를 별도 보관합니다.
4. `*p = 9u` 뒤에는 level=9, before=5, p=&level입니다.
5. 세 assert가 이 결과를 검산합니다. 성공하면 출력 없이 종료합니다.

여기서 RAM 대신 주변장치가 연결된 주소를 읽고 쓴다면 어떨까요? **메모리 매핑 입출력(MMIO)** 은 주소 공간의 일부를 주변장치 레지스터에 대응시키는 방식입니다. 특정 주소 쓰기를 장치가 설정이나 명령으로 해석합니다. C 대입의 겉모양이 같아도 대상은 일반 RAM과 다를 수 있습니다. 다음 레슨부터 비트 설정과 접근 규칙을 붙입니다.

## 헷갈리기 쉬운 점

- 주소를 안다고 바로 접근할 수 있는 것은 아닙니다. 실제 MCU에서는 메모리 지도, 허용 접근 폭, 주변장치 클록 등 전제를 확인해야 합니다.
- 예제의 0x2000은 설명용입니다. 실행 코드에는 실제 주소로 사용하지 않았습니다.
- Jetson의 Linux 사용자 프로그램에서 물리 주소를 포인터로 바꾸는 것만으로 주변장치를 제어할 수 있다고 생각하면 안 됩니다. 가상 메모리·권한·드라이버 경로를 고려해야 합니다.
- CPU 내부 연산용 레지스터와 GPIO·UART 같은 주변장치 레지스터는 역할이 다릅니다. 이 트랙의 레지스터 제어는 문맥상 주변장치를 뜻합니다.

## 직접 확인하기

1. `p = &level`과 `*p = 9u` 중 대상의 값을 바꾸는 것은 무엇인가요?
2. 마지막에 before가 9로 바뀌지 않는 이유는 무엇인가요?
3. MMIO에서 같은 C 대입이 RAM 대입과 다른 결과를 만드는 이유는 무엇인가요?

## 참고 범위

주소·포인터 코드는 자체 일반 C 예제이고 메모리 지도는 교육용입니다. MMIO 연결은 [Arm CMSIS의 주변장치 접근 설명](https://arm-software.github.io/CMSIS_6/latest/Core_A/group__peripheral__gr.html)을 참고했습니다. 링크는 Cortex-A 문서이므로 Cortex-M4의 주변장치 주소·접근 규칙을 대신하지 않습니다. 실제 STM32 초기화나 사용자 프로젝트 소스를 재현한 예제는 아닙니다.
