## 이번 레슨의 목표

비트 마스크로 설정·해제·검사하고, 여러 비트로 된 필드를 다른 설정을 보존하며 바꿀 수 있습니다. 코드를 읽기→계산→쓰기로 풀어 설명합니다.

## 앞에서 배운 내용

주소는 위치이고 `*p`는 대상의 값에 접근합니다. 이번에는 주소를 잠시 빼고 값만 계산합니다. 일반 RAM 변수에서 연습하며, 실제 레지스터에 그대로 적용할 수 있는지는 다음 레슨에서 따집니다.

## 개념과 동작

비트 번호는 오른쪽부터 0입니다. **마스크(mask)** 는 관심 있는 비트 자리에 1을 놓은 값입니다. 8비트로 그린 `0000 1000`은 비트 3의 마스크이며 16진수로 0x08입니다.

| C 연산 | 비트 하나에서의 뜻 | 용도 |
| --- | --- | --- |
| `a \| b` | 둘 중 하나라도 1이면 1 | 비트 켜기 |
| `a & b` | 둘 다 1이면 1 | 비트 선택 |
| `~a` | 각 비트 반전 | 지울 자리의 반대 마스크 |
| `a << n` | 왼쪽으로 n자리 이동 | 필드 위치 맞추기 |
| `a >> n` | 부호 없는 값에서 오른쪽 이동 | 필드 값 꺼내기 |

`|`는 비트 OR이고 `||`는 논리 OR입니다. `&`도 두 값 사이에서는 비트 AND, 변수 앞에서는 주소 연산자입니다. 식의 위치를 보고 구별합니다.

## 코드 읽기

일반 C11 예제입니다. 낮은 8비트만 그림으로 보여주지만 계산 대상은 `uint32_t`입니다. 비트 5:4는 모드 필드이고 새 모드는 2라는 조건입니다. 여기서 5:4는 5번과 4번 비트 두 개를 뜻합니다.

```c
#include <stdint.h>
#include <assert.h>

int main(void)
{
    uint32_t config = 0xA5u;
    const uint32_t mode_mask = 3u << 4;
    config = (config & ~mode_mask) | (2u << 4);
    assert(config == 0xA5u);

    config |= 1u << 3;
    assert(config == 0xADu);
    config &= ~(1u << 0);
    assert(config == 0xACu);
    assert((config & (1u << 3)) != 0u);
    assert(((config >> 4) & 3u) == 2u);
    return 0;
}
```

`3u`는 이진수 11이므로 `3u << 4`는 0x30입니다. `~mode_mask`는 필드 자리만 0인 마스크가 됩니다. AND로 기존 필드를 지운 뒤 OR로 새 필드를 넣습니다. 이 예에서는 처음 필드도 이미 2라 첫 대입의 결과가 그대로입니다. 설정 함수가 값을 반드시 바꿔야 하는 것은 아닙니다.

`config |= mask`는 이 변수에서 `config = config | mask`와 같은 결과를 내고, `&=`는 AND 결과를 다시 저장합니다. 검사식에서 `!= 0u`는 선택한 비트가 켜져 있는지 참·거짓으로 바꿉니다.

## 따라 풀기

첫 대입을 낮은 8비트로 추적합니다. 상위 비트는 처음부터 0이고 그대로입니다.

| 단계 | 비트 패턴 | 값 |
| --- | --- | --- |
| 처음 | 1010 0101 | 0xA5 |
| 필드 5:4 지우기 | 1000 0101 | 0x85 |
| 새 필드 2 삽입 | 1010 0101 | 0xA5 |
| 비트 3 켜기 | 1010 1101 | 0xAD |
| 비트 0 끄기 | 1010 1100 | 0xAC |

필드만 바뀌어야 하므로 기존 값과 결과에서 `~mode_mask`로 뽑은 부분이 같아야 합니다. 새 모드를 1로 바꾸면 결과는 0x95가 됩니다. 단순히 `config |= 1u << 4`만 하면 기존 필드 10에 01이 합쳐져 11이 되므로 교체가 아닙니다.

## 헷갈리기 쉬운 점

- `config = 1u << 3`은 나머지 비트를 모두 0으로 덮어씁니다. 보존이 필요하면 OR를 사용합니다.
- 이 예제의 새 필드 값은 0부터 3까지입니다. 외부 입력을 받는 실제 함수라면 범위를 먼저 검증해야 합니다. 마스크로 잘라내는 것과 잘못된 입력을 거절하는 것은 다릅니다.
- 시프트 수는 왼쪽 피연산자의 승격 후 비트 폭보다 작아야 합니다. 여기서는 32비트 이상인 unsigned int를 제공하는 호스트·STM32 환경을 전제합니다. AVR처럼 unsigned int가 16비트인 환경에 높은 비트 시프트를 그대로 옮기지 않습니다.
- RAM에서 맞는 계산이 실제 레지스터에서도 안전하다는 뜻은 아닙니다. 읽기·쓰기 부작용과 인터럽트의 개입을 다음에 살펴봅니다.

## 직접 확인하기

1. 0xA5에서 비트 3만 켜면 얼마인가요?
2. 비트 5:4를 1로 교체한 값은 얼마인가요? 왜 OR만으로는 부족한가요?
3. 비트 3이 켜져 있는지 검사할 때 `config & 3u`로 해도 될까요?

<details>
<summary>정답과 이유</summary>
<p>1. 0xAD입니다. 0x08을 OR하며 다른 비트는 보존합니다.</p>
<p>2. 0x95입니다. 기존 필드를 지운 0x85에 0x10을 OR합니다. OR만 하면 기존의 1을 지우지 못해 0xB5가 됩니다.</p>
<p>3. 안 됩니다. 3은 비트 번호가 아니라 값 0b11이므로 비트 1과 0을 선택합니다. 비트 3 마스크는 1u &lt;&lt; 3, 즉 8입니다.</p>
</details>
