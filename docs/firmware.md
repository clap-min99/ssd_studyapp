# 펌웨어 동작 원리: 설계와 제작 기준

## 목표와 독자

STM32·AVR·Jetson Orin Nano 실습 경험을 바탕으로, 사용했던 코드의 동작을
주소·값·시간·실행 주체 관점에서 설명하는 한국어 학습 트랙이다.
앱에서 읽는 것만으로 개념과 코드의 연결을 따라갈 수 있게 만들고, 보드 확인은 선택 실습으로 둔다.
컴퓨터 구조 트랙 완주를 선수 조건으로 삼지 않고 필요한 비트·메모리 개념을 해당 레슨에서 복습한다.

사용자 포트폴리오 README에서 MotorControl의 레지스터·PWM·EXTI,
GasMonitoring의 UART 통신, AVR 프로젝트의 FSM·타이머·I²C 경험을 확인했다.
소스를 검토하지 않았으므로 버그나 숙련도를 단정하거나 자체 예제를 사용자 코드라고 표시하지 않는다.
실제 코드 연결은 해당 파일·커밋을 읽은 후 추가한다.

## 자료의 역할

- [Making Embedded Systems, 2판](https://www.oreilly.com/library/view/making-embedded-systems/9781098151539/): 전체 흐름을 설계하는 참고서. 목차 확인 단계이며 본문을 읽고 재구성한 강의라고 표시하지 않는다.
- [STM32F411 공식 문서 목록](https://www.st.com/en/microcontrollers-microprocessors/stm32f411/documentation.html)의 RM0383: 실제 주변장치 동작의 기준. 현재는 문서 안내와 검색 발췌 확인 단계다. 주소·비트·초기화 순서를 사용하는 실보드 예제를 추가하기 전에 해당 절 본문과 디바이스 헤더를 대조한다.
- [Arm CMSIS Cortex-M4 헤더](https://github.com/ARM-software/CMSIS_4/blob/master/CMSIS/Include/core_cm4.h): 접근 한정자와 코어 코드 참고. 보관된 구버전이므로 향후 실습 환경의 CMSIS 버전도 기록한다.
- FreeRTOS 공식 문서, OSTEP, NVMe 공식 명세: 각 심화 장 제작 시 실제 범위를 읽고 출처를 연결한다.
- [사용자 포트폴리오](https://github.com/clap-min99/pjt_portfolio): 경험과 예제 주제 연결.

원문·그림·문제를 복사하지 않는다. 자체 교육용 모델과 실제 칩 동작을 구별한다.
확인하지 않은 페이지·절 번호를 붙이지 않고 레슨마다 사용한 자료와 검증 한계를 기록한다.

## 전체 설계

아래 레슨 주제는 제작 계획이며, 완성 레슨만 앱에 등록한다. 분량보다 한 질문의 완결성을 우선한다.

| 장 | 레슨 주제 | 장을 마친 뒤 할 수 있는 것 | 경험 연결 |
| --- | --- | --- | --- |
| 1. C 코드에서 레지스터까지 | 주소·포인터 / 비트·필드 / volatile·접근 부작용 | 한 줄을 읽기·계산·쓰기로 풀고 전후 값을 계산 | STM32 레지스터 제어 |
| 2. 부팅과 메모리 | 벡터·리셋 / .data·.bss·스택 / 링커·map / 수명·메모리 손상 | 전원 인가에서 main까지, 변수가 놓이는 곳 설명 | AVR·STM32 초기화 |
| 3. 인터럽트 | 폴링과 이벤트 / 벡터·NVIC / 우선순위·지연 / ISR·메인 경쟁 / 디바운스 | 요청·pending·실행·복귀를 시간순으로 추적 | MotorControl EXTI |
| 4. 타이머와 PWM | 클록 트리 / PSC·ARR·주기 / 비교·듀티 / 입력 캡처 / 비차단 타임아웃 | 명시한 클록 조건에서 주기·해상도 계산 | 모터·초음파·세탁기 |
| 5. UART와 수신 처리 | 프레임·baud / 폴링·인터럽트 / 링 버퍼 / 패킷 파서 / 오버런·복구 | 바이트 스트림에서 메시지를 조립하고 손실 설명 | GasMonitoring·AutoCar |
| 6. DMA와 버퍼 | 전송 경로 / 완료·순환 모드 / 소유권·수명 / 처리량·역압 | 전송 중 버퍼 수정이 왜 위험한지 추적 | UART 수신 확장 |
| 7. FSM과 RTOS | 이벤트·상태 / 태스크·큐 / 임계구역·뮤텍스 / 우선순위 역전·데드라인 | 실행 주체별 공유 데이터와 동기화 선택 | 기존 FSM 재해석 |
| 8. 디버깅과 복구 | 브레이크포인트·로그 / fault·스택 / watchdog / 오류 주입·복구 상태 | 관찰→가설→재현→수정 절차 적용 | 통신 끊김·제어 정지 |
| 9. SSD로 연결 | 호스트 요청·완료 / 플래시·FTL / GC·버퍼 / 전원 장애·메타데이터 | 기존 SSD 트랙과 실행 흐름 연결 | SSD/NAND 학습 |

SPI·I²C·CAN은 UART 장 이후 별도 확장 후보다. 현재 구현 범위에 넣지 않는다.
Jetson의 Linux 사용자 프로그램과 MCU 베어메탈의 실행 환경 차이는 비교 설명으로 다루고,
GPU·AI 추론·Linux 드라이버 전체 과정은 별도 트랙이 필요할 때 설계한다.

## 레슨 작성 형식

1. `이번 레슨의 목표`: 관찰 가능한 설명·계산 목표.
2. `앞에서 배운 내용`: 필요한 선수 지식과 이미 해본 실습 연결.
3. `개념과 동작`: 용어 정의→왜 필요한가→그림·표로 동작 설명.
4. `코드 읽기`: 실행 가능한 C 조각 또는 명시한 의사코드. 줄별 연산·자료형·전제 설명.
5. `따라 풀기`: 입력·초기 상태→중간 값→결과→검산. 시간 문제에는 단위와 클록 조건 포함.
6. `헷갈리기 쉬운 점`: 실패 사례와 적용 범위.
7. `직접 확인하기`: 설명·값 추적·오류 판별 3문제 이상, 접이식 답과 이유.
8. `다음으로 이어가기`: 현재 완성 범위와 다음 계획을 구분.
9. `참고 범위`: 직접 확인한 자료·자체 보충·검증 한계.

한 레슨의 핵심 코드에는 전제와 예상 결과가 모두 있어야 한다. 코드만 길게 붙여 두지 않는다.
처음 나오는 C 문법도 포인터·역참조·연산자부터 해설한다. 넓은 코드·표를 피하고
한국어 용어 뒤에 영어를 병기한다. 기존 Markdown·details·인라인 SVG 렌더러를 사용한다.
그림에는 viewBox, role, title, desc, aria-labelledby를 넣고 색 외에 텍스트로 의미를 전달한다.
지원하지 않는 Mermaid·실행형 위젯·런타임 AI 생성은 도입하지 않는다.

## 코드와 하드웨어 검수

- 일반 C와 STM32F411 전용 코드, AVR 차이, 교육용 의사코드를 명시한다.
- 실주소 예제는 해당 문서의 접근 폭·정렬·클록·핀 설정·플래그 해제 절차까지 확인한다.
- volatile은 원자성·상호배제·DMA 일관성을 보장한다고 설명하지 않는다.
- RMW는 일반 R/W 설정과 W1C·읽기 부작용 레지스터에서 구분한다.
- 정상 경로와 버퍼 포화·시간 초과·인터럽트 경쟁 같은 경계 사례를 함께 검토한다.
- 일반 C 예제는 가능하면 호스트에서 컴파일·assert로 확인한다. 단순 값 추적도 자동 검산한다.
- 시드 반복 실행의 ID 보존, 다른 트랙 보존, API 탐색, 실패 시 롤백을 테스트한다.
- 실제 렌더러에서 코드·표·접기·그림 보존을 확인한다. 브라우저 모바일 육안 검사와 보드 검증은 별도로 기록한다.

## 구현과 반영

기존 Tag·Lesson·API·LessonDetail을 사용한다. category=`firmware`를 추가하고,
Markdown은 `digest/content/firmware/chapterNN/`에 둔다.
`seed_firmware`는 완성된 첫 장만 원자적으로 upsert한다. slug와 레슨 order는 URL·ID 유지용이므로
기존 레슨을 재배치하지 않는다. 다른 트랙 수정·레슨 삭제는 하지 않는다.
새 장 제작 시 명시적인 목록과 prerequisite 연결을 추가하고 탐색 테스트를 확장한다.

개발 DB 연결을 확인한 뒤 실행:

```text
python manage.py migrate
python manage.py seed_firmware
```

연결 대상은 DATABASE_URL이 결정한다. 서비스 DB 시드·배포는 이번 작업에 포함하지 않는다.
초기 반영은 별도 로컬 SQLite 파일로 검증한다.

## 제작 현황 — 2026-10-26

- 초안 작성: 1장 3레슨(주소·포인터, 비트·필드, 레지스터 접근 규칙).
- 예제는 자체 RAM 모델과 교육용 레지스터 규칙이다. STM32의 실제 초기화 코드나 사용자 소스의 재현이 아니다.
- 2–9장은 설계만 완료했으며 빈 레슨·빈 챕터를 앱에 만들지 않는다.
- 다음 제작: 부팅·메모리 장. 이후 인터럽트·타이머·UART 순서로 진행한다.

로컬 미리보기 DB는 `reports/firmware-preview.sqlite3`에 생성했다(커밋 제외).
이 데이터를 앱에서 보려면 백엔드 실행 시 `DATABASE_URL=sqlite:///reports/firmware-preview.sqlite3`를 지정한다.
평소 사용하는 DB에는 위 migrate·seed 명령을 별도로 실행해야 한다.

### 초기 검증 결과

- 펌웨어·기존 컴퓨터 구조 테스트 16개 실행: 실패 없음. C 실행 검사 중 2개 하위 사례는 Windows 접근 거부로 건너뛰었다.
- C11 예제 3개 모두 GCC에서 `-Wall -Wextra -Werror -O2` 컴파일 성공. volatile 예제는 실행 성공, 주소·비트 예제의 실행은 OS가 차단했다. 비트·W1C 본문 계산은 별도 자동 검사 통과.
- 프런트 테스트 30개와 프로덕션 빌드 통과. 실제 Markdown 렌더러에서 C 코드·표·접이식 정답·SVG 보존 확인.
- 별도 SQLite DB에 전체 마이그레이션·첫 장 시드 성공. 모델과 마이그레이션 차이 없음.
- 실보드 검증, 서비스 DB 반영·배포는 수행하지 않았다.

### 실제 브라우저 추가 검사 — 2026-10-26

로컬 Django API·미리보기 SQLite·Vite에 설치된 Chrome을 연결해 검사했다.
인증은 미리보기 DB에만 만든 테스트 계정으로 실제 세션 로그인 API를 사용했다.

- 1440×1000, 390×844, 320×740에서 각 3레슨, 총 9화면 통과.
- 펌웨어 트랙 선택→챕터→첫 레슨→다음 레슨→이전 레슨 이동 확인.
- 다음 레슨은 맨 위에서 시작하는지 확인. 코드 블록·표·접이식 정답 표시와 펼치기 확인.
- 페이지 가로 넘침 없음. 긴 코드 줄은 코드 블록 안에서 가로 스크롤된다.
- 브라우저 JS 오류·API 4xx/5xx 없음. 데스크톱·모바일 스크린샷도 열어 확인했다.
- 스크린샷 9개와 수치 결과: `reports/browser-check/` (커밋 제외).
- 재검사 스크립트: `scripts/check_firmware_browser.cjs`. Playwright Core를 위 임시 폴더에 설치하고 로컬 서버와 미리보기 계정을 준비한 뒤 `FIRMWARE_PREVIEW_PASSWORD`를 지정하여 실행한다. Windows Chrome 전용 검사이며 앱의 의존성을 추가하지 않는다.
- C 실행도 재검사했다. 세 예제 모두 컴파일 성공, volatile 예제 실행 성공. 주소·비트 예제는 `PermissionError / WinError 5`가 재현되어 실행 성공으로 표시하지 않았다. 접근 거부의 구체적인 보안 제품·정책 원인은 확인하지 못했다.
